# PRD — FabGraph

> FabGraph는 `cypher-graph`의 후속 프로젝트로, **반도체 제조 데이터용 Hybrid DB + Multi-Agent 분석 워크스페이스**를 목표로 합니다.

## 1. 제품 개요

FabGraph는 반도체 제조 데이터를 자연어로 탐색하고, 그 결과를 **그래프 / 테이블 / 차트 / 대화형 응답**으로 통합 제공하는 분석 워크스페이스입니다.

이 제품이 해결하려는 핵심 문제는 다음과 같습니다.
- 제조 데이터가 정형 테이블과 관계 구조로 나뉘어 있어 한 번에 보기 어렵다.
- 엔지니어가 SQL, Cypher, 시각화 도구를 각각 따로 다뤄야 한다.
- 질의, 관계 탐색, 통계 분석, 시각화가 하나의 흐름으로 연결되지 않는다.

현재 구현은 thin-slice 중심이지만, 장기적으로는 **실데이터 + 실제 에이전트 오케스트레이션**을 갖춘 분석 플랫폼으로 확장하는 것을 목표로 합니다.

---

## 2. 목표

### 핵심 목표
1. 자연어 기반으로 제조 데이터를 조회할 수 있어야 한다.
2. 정형 조회는 PostgreSQL, 관계 탐색은 Neo4j로 분리 처리해야 한다.
3. 결과는 그래프, 테이블, 차트, 텍스트로 함께 제공되어야 한다.
4. 계산과 분석은 LLM이 아니라 코드 기반 도구가 수행해야 한다.
5. 이후 예측형 기능(레시피→계측, 계측→레시피)으로 확장 가능해야 한다.

### 비목표
- 범용 사내 챗봇 구축
- 모든 제조 도메인 업무 자동화
- 초반부터 실시간 CDC 파이프라인 필수 도입
- 복잡한 권한/승인 체계의 즉시 구축

---

## 3. 사용자

### 주 사용자
- 공정 엔지니어
- 분석 엔지니어
- DOE / 레시피 / 계측 이력을 추적하는 개발 조직

### 사용 맥락
- 특정 공정(stepseq)의 최신 웨이퍼를 빠르게 보고 싶다.
- 특정 장비 / 챔버 / PPID 조건으로 웨이퍼를 필터링하고 통계를 보고 싶다.
- 같은 DOE 또는 같은 시기에 평가된 웨이퍼 그룹을 관계로 보고 싶다.
- 레시피 변화와 계측 결과 사이 패턴을 장기적으로 분석하고 싶다.

## 4. 유스케이스 범위

### Phase 1 포함
- UC1 최신 웨이퍼 조회
- UC2 조건부 필터링 + 기본 통계
- UC3 DOE / 동시기 평가 그룹 탐색

### Phase 2 포함
- 이상치 탐지
- 상관 분석
- 차트 추천 및 자동 생성
- 그룹 비교 리포트

### Phase 3 포함
- UC5 레시피 → 계측 예측
- UC6 계측 → 레시피 탐색

## 5. 사용자 스토리

### US-01
사용자는 자연어로 “UR123111 공정의 최신 웨이퍼 20개 보여줘”라고 묻고, 결과를 테이블과 차트로 받고 싶다.

### US-02
사용자는 “ETCH_EQP_01의 3번 챔버에서 처리된 웨이퍼들의 CD 평균과 이상치를 보여줘”라고 묻고, 통계 요약을 받고 싶다.

### US-03
사용자는 “DOE-2024-A에 속한 웨이퍼들을 그래프로 보여줘”라고 묻고, 관계 기반 시각화를 보고 싶다.

### US-04
사용자는 “RF Power와 CD 사이 관계를 보고 싶다”라고 묻고, 산점도와 요약 설명을 받고 싶다.

## 6. 성공 기준

### 기능 성공 기준
- 사용자가 자연어 질문으로 결과를 얻을 수 있다.
- SQL / Cypher / 분석 / 시각화가 하나의 응답 흐름으로 연결된다.
- 그래프 / 테이블 / 차트가 서로 선택 상태를 공유한다.

### 제품 성공 기준
- 엔지니어가 수작업 쿼리 시간을 줄일 수 있다.
- 같은 질문에 대해 반복 가능한 구조화된 응답을 제공한다.
- PoC를 넘어 다음 기능을 얹을 수 있는 플랫폼 구조를 갖춘다.

- 실시간 동기화 파이프라인
- 예측 모델 자동 서빙

---

## 8. UX 원칙

1. 질문은 자연어로 시작한다.
2. 중간 단계는 보여주되, 최종 결과는 간결해야 한다.
3. 그래프 / 테이블 / 차트는 각각 따로 노는 화면이 아니라 하나의 작업 공간이어야 한다.
4. 사용자는 어떤 DB가 쓰였는지 몰라도 되지만, 시스템 내부 구조는 명확히 분리돼 있어야 한다.
5. 결과에는 항상 재현 가능한 구조(raw rows / graph / chart spec)가 남아야 한다.
